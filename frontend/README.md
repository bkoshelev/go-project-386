# Frontend

React/TypeScript-приложение запускается и проверяется из каталога `frontend/`.

## Команды качества

| Команда             | Назначение                                                |
| ------------------- | --------------------------------------------------------- |
| `pnpm lint:code`    | Проверить JS, TS, JSX и TSX с анализом типов              |
| `pnpm lint:css`     | Проверить обычные CSS-файлы                               |
| `pnpm lint`         | Последовательно выполнить обе lint-проверки               |
| `pnpm lint:fix`     | Применить безопасные автоисправления Oxlint и Stylelint   |
| `pnpm format`       | Отформатировать поддерживаемые frontend-файлы через Oxfmt |
| `pnpm format:check` | Проверить форматирование без изменения файлов             |
| `pnpm check`        | Выполнить lint, затем проверить форматирование            |

Исправления запускаются только явно: lint и CI исходники не изменяют. `pnpm build`
по-прежнему выполняет отдельную проверку TypeScript перед production-сборкой.

Подавление допускается для конкретного правила на минимальном участке кода. Рядом
нужно оставить комментарий с причиной исключения. Oxlint и Stylelint сообщают о
подавлениях, которые больше не нужны.

Для редактора можно установить расширения Oxlint, Oxfmt и Stylelint. Интеграция
необязательна; источником истины остаётся `pnpm check`. Для Oxlint в редакторе
нужно включить type-aware linting, как в `.oxlintrc.jsonc`.

Oxlint выполняет статические проверки JSX-доступности. Они не знают семантику всех
компонентов Mantine, особенно полиморфных компонентов с параметром `component`.
Конфигурация намеренно не сопоставляет все компоненты Mantine с HTML-тегами.
Успешный lint поэтому не заменяет проверку доступности интерфейса в браузере.
