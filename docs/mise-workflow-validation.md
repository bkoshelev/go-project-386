# Проверка окружения mise

Дата: 7 ноября 2026. Спецификация: [mise development workflow](../specs/mise-development-workflow.md).

Проверено на macOS amd64, mise 2026.10.17, hk 2.11.1, pitchfork 2.33.1,
PostgreSQL 18.6. Hk и pitchfork собраны Cargo backend mise с Rust 1.95.0:
официальных готовых бинарников macOS Intel у этих версий нет.
Версии приложения не обновлялись. Lockfile сформирован штатным `mise lock`
для macOS/Linux amd64/arm64; нативные arm64-окружения отдельно не запускались.

## Результаты

- `mise tasks validate`: 46 задач; `mise fmt --check`, `hk validate`,
  синтаксические проверки shell/Node и actionlint для изменённых workflows прошли.
- `mise run workflow:test`: 8 тестов. Проверены типы release-политики, scope,
  breaking marker, отклонение некорректных сообщений, строгие заголовки PR,
  shell-символы как данные, неизменность сообщения. Реальные commits проверены
  launcher во временном Git-репозитории с пробелами, кавычкой и `$()` в пути;
  установлен только `commit-msg`, глобальный Git config не изменился.
- `mise run backend:check`: lint, sqlc-check, vet, все тесты с `-race -count=1`,
  сборка и govulncheck прошли. Вызываемых уязвимостей нет. `backend:test-unit`
  также прошёл с заведомо недоступным Docker socket.
- `backend:api-generate` воспроизводит сохранённые Go-артефакты без изменений.
- Frontend quality, typecheck и production build прошли; все 96 тестов
  Playwright прошли через `frontend:test-smoke`.
- `container:test` собрал production-образ через задачи mise и прошёл существующий
  smoke: браузер, один origin, миграции, сохранность данных, отказ/восстановление
  БД, сигналы завершения и очистка изолированных ресурсов. Первый запуск встретил
  HTTP 503 Debian mirror; повторная сборка и smoke прошли. Runtime-стадия содержит
  только приложение и ресурсы frontend, без mise/hk/pitchfork.
- Чистый worktree без `.env.local` подготовлен bootstrap Orca без shell activation.
  `SETUP_VERIFY=1` прошёл весь backend/frontend-набор, включая 96 браузерных тестов.
  Повторный обычный setup успешен. Удаление API lock-файла во временном worktree
  вызывает ошибку явного setup; после восстановления setup снова успешен.
- Обычный `mise install` запускает подготовку через postinstall ровно один раз,
  без рекурсии. Неверный `SETUP_VERIFY` и отсутствие mise диагностируются.
  `doctor` проверен до установки hk (ошибка) и после подготовки (успех).
- Два временных worktree одновременно запустили полный нативный стек:
  PostgreSQL на 5551/5442, backend на 8199/8090, frontend на 5292/5183.
  IDs процессов, каталоги данных и порты раздельные. Созданные через HTTP типы
  событий доступны только в своём worktree, включая запросы через Vite proxy.
- Остановка/повторный запуск сохраняют данные; restart frontend, состояние и
  логи работают. Занятый порт backend приводит к ошибке, владелец порта остаётся
  жив. `dev:db-reset` очищает только выбранную БД, данные второго стека сохраняются.
  Запуск frontend после очистки снова поднимает зависимости и готовый пустой каталог.
- `.env.local` разных worktree изолированы; отсутствие файла допустимо.
  Регрессионный тест подтверждает, что `.env.local` не отменяет `GOTOOLCHAIN=local`.

GitHub Actions после публикации не запускались. Локальная проверка синтаксиса
workflows и чтения PR event JSON не заменяет запуск на GitHub.

## Standards

Документированных нарушений стандартов не обнаружено. Неблокирующее замечание
ревью: possible Duplicated Code — setup и doctor повторяют явный список инструментов.
Списки намеренно ограничивают операции инструментами проекта, исключая родительские
конфигурации; при добавлении инструмента их нужно обновлять вместе с `[tools]`.

## Spec

Ревью нашло оставшиеся вызовы удалённых package scripts в справочнике React DevTools
(AC-01); они заменены задачами mise. Проверка dotenv выявила возможность отменить
`GOTOOLCHAIN=local`; порядок загрузки исправлен, добавлен проходящий тест.
Других подтверждённых расхождений со спецификацией ревью не обнаружило.

Итог ревью: Standards — 0 нарушений, 1 неблокирующее замечание; Spec —
1 замечание исправлено, открытых замечаний нет.

## Уточнения по итогам ревью 8 ноября 2026 года

Обработаны пять согласованных замечаний: русские описания задач и их происхождение,
построчные русские комментарии в файловых задачах и Dockerfile, явные точные версии
Go, Node.js и pnpm в `mise.toml`. Обновлены Q4, критерии приёмки, ADR-0018,
README и актуальные требования к Go-проверкам.

- Все 46 описаний задач проверены на русский текст и указание прежнего файла
  с командой либо новизны задачи. Комментарии покрывают все строки кода файловых
  задач начиная с третьей и содержательные строки Dockerfile. Сравнение с `HEAD`
  после исключения комментариев подтвердило сохранение исполняемых команд.
- `mise tasks validate`, `mise fmt --check`, `mise run doctor`, `bash -n`
  для всех семи файловых задач и `git diff --check` прошли.
- `mise run workflow:test`: 9 тестов прошли, включая новый регрессионный тест
  разрешения точных версий Go, Node.js и pnpm из изолированной копии `mise.toml`
  без языковых файлов. Форматирование изменённого теста проверено Oxfmt.
- `docker build --check --progress plain .` завершился без предупреждений;
  продолжения инструкций Dockerfile после добавления комментариев корректны.
- Явные версии Go 1.26.10, Node.js 24.21.0 и pnpm 12.4.2 совпадают с языковыми
  декларациями и записями `mise.lock` для всех четырёх поддерживаемых платформ.
  `mise lock go node pnpm` обновил метаданные Go и Node.js без изменения lock-файла.
  Повторная проверка provenance pnpm пропущена для четырёх платформ из-за HTTP 504
  при скачивании с GitHub; существующие записи pnpm сохранены без изменений.
