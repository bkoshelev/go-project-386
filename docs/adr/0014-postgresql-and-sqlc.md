# PostgreSQL и типизированные SQL-запросы через sqlc

Статус: принято; итоговый дизайн утверждён пользователем 19 октября 2026 года.

Для backend выбраны PostgreSQL и внутренний Go-пакет, генерируемый sqlc из
SQL-запросов и схемы. SQL остаётся явно написанным источником запросов;
генерируемый пакет служит для обращения к БД внутри backend и не является
отдельным публичным SDK. Выбор закрепляет SQL-подход вместо ORM и позволяет
проверять запросы и типы при генерации кода; смена СУБД потребует пересмотра SQL.

Первое внедрение ограничено инфраструктурой и одним сквозным примером:
миграция схемы, генерация Go-кода и выполнение запроса к реальной тестовой БД.
Полная схема приложения добавляется при реализации соответствующих функций.
Окружение БД в этой задаче запускается только на время тестов; постоянная
локальная БД и Docker Compose в объём не входят.

Выбраны PostgreSQL 18 с закреплённой patch-версией образа, goose для миграций,
pgx/v5 для подключения и testcontainers-go для временной тестовой БД. Проверки
используют уже установленный testify. Сгенерированный Go-код хранится в Git,
чтобы обычная сборка не требовала sqlc; CI проверяет актуальность генерации.

Полный запуск `make test` и CI включает тесты БД и требует доступный Docker.
Ошибка запуска контейнера делает проверку неуспешной, а не пропущенной.
Отдельный `make test-unit` позволяет запускать тесты без Docker. Это уточняет
окружение полного запуска тестов из ADR-0011, сохраняя его назначение.

SQL-миграции goose служат единственным источником схемы для sqlc. Встроенные
SQL-файлы использует общий Go-пакет миграций, доступный тестам и отдельной
команде `cmd/migrate`; операции также доступны из корневого Makefile.

Обычные тесты используют общий контейнер на пакет и отдельную транзакцию
на тест с явным откатом в `t.Cleanup`. Дополнение, согласованное пользователем
20 октября 2026 года: после миграций и до запуска тестов testfixtures один раз
загружает общий исходный YAML-набор. Каждый тест читает и меняет его в своей
откатываемой транзакции; загрузчик не очищает таблицы между тестами.
Общий контейнер сокращает число запусков БД. Транзакция на тест
не подходит для будущих проверок, которым нужен реальный `COMMIT`
или взаимодействие нескольких соединений. Сам цикл миграций проверяется
в отдельной временной базе общего контейнера без внешней тестовой транзакции.
