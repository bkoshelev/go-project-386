# ADR-0009: Go 1.26 и закреплённые инструменты backend

Статус: принято; реализовано.

## Контекст

В текущем модуле и README указана Go 1.27.1. Во время интервью пользователь
уточнил, что проект должен работать на Go 1.26. Рассматривались первый релиз
1.26.0 и актуальный исправленный релиз ветки 1.26. Для анализаторов выбирали
между явными обновлениями закреплённых версий и автоматическими PR обновлений.

## Решение

Целевая ветка — Go 1.26, первоначально закрепить patch 1.26.8. Версию хранить
в backend/go.mod, использовать в CI и документировать в README. Проверять
приложение именно этой версией, без незаметного перехода на более новую ветку.
Не изменять системную установку Go пользователя автоматически.

Версии golangci-lint и govulncheck закрепить отдельно от зависимостей приложения
в корневом Makefile. Использовать бинарники из backend/bin/tools/, а не случайную
установку в PATH. Обновления версий и состава правил — явные изменения проекта
с проверкой совместимости. Автоматические обновления не настраивать.

## Последствия

- Переход с указанной в репозитории Go 1.27.1 на 1.26.8 намеренный, а не опечатка.
- Совместимость проверяется сборкой и тестами на целевом toolchain, а не только
  чтением минимальных версий зависимостей.
- Нельзя использовать возможности Go 1.27 в приложении без нового решения
  о целевой ветке. Поддержка ветки и обновление patch требуют внимания команды.
- Версия Go сборки анализатора может быть выше целевой версии приложения;
  требование к приложению и требования бинарника инструмента различаются.
- Если переход требует смены версий зависимостей приложения, это отдельный
  блокер: такие изменения не разрешены в задаче подключения линтеров.

## Почему решение сохранено

Это реальный выбор целевой платформы и политики обновлений. Понижение указанной
версии Go удивит читателя без контекста. После появления кода и CI, опирающихся
на этот контракт, его пересмотр требует проверки всего backend; это не
необратимое решение, но и не локальная правка конфигурации линтера.
