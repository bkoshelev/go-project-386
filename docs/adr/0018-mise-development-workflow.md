# ADR-0018: Mise как общий интерфейс окружения разработки

Статус: принято; старт реализации явно одобрен пользователем 7 ноября 2026 года.
Уточнение по итогам ревью и старт его реализации одобрены 8 ноября 2026 года.

Команды подготовки, запуска, генерации, сборки и проверок определяются задачами
mise и вызываются разработчиком, агентом, CI и стадиями сборки контейнера.
Предыдущая организация через Makefile и package scripts заменяется, поскольку
одни и те же сценарии должны использовать общее окружение и зависимости шагов.
Точные версии Go, Node.js и pnpm явно задаются в `mise.toml` вместе с версиями
остальных инструментов, а метаданные установок фиксируются в `mise.lock`.
По итогам ревью это решение заменило первоначальное чтение версий из языковых
файлов через шаблоны. Декларации в `go.mod`, `.nvmrc` и package.json сохраняются
для соответствующих языковых инструментов и обновляются согласованно с mise.
`doctor` проверяет соответствие выбранных инструментов `go.mod`, `.nvmrc`
и `packageManager` frontend. Direnv заменяется загрузкой локального env-файла
средствами mise.

PostgreSQL разработки, backend и frontend управляются mise daemons с явным
запуском и остановкой и изоляцией процессов, портов и данных между worktree.
Пользователь принял экспериментальный статус mise daemons и необходимую
зависимость pitchfork; её версия закрепляется. Тестовые БД сохраняют собственный
жизненный цикл. Остановка dev-стека сохраняет данные, очистка вызывается отдельно.

Hk устанавливается только для репозитория и обслуживает единственный Git hook
`commit-msg`, проверяющий Conventional Commits. `pre-commit` и `pre-push`
исключены по выбору пользователя. Для squash merge локальную проверку дополняет
CI-проверка заголовка PR. Release-please продолжает готовить релизы после push
в main; валидатор сообщений использует согласованный с ним список типов.

Это решение заменяет [ADR о корневом Makefile](0011-root-makefile.md)
в части источника команд и установки backend-инструментов и
[ADR frontend quality gate](0011-frontend-quality-gate.md) в части отказа
от Git hooks. Политика качества и разделение проверок и исправлений сохраняются.
Настройки предметной области и производственный runtime не изменяются.

Требования, границы и проверка: [спецификация](../../specs/mise-development-workflow.md).
