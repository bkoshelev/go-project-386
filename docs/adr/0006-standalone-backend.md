# ADR-0006: Самостоятельный компактный backend

Статус: принято.

## Контекст

В репозитории уже есть самостоятельный frontend, Go-кода пока нет. В интервью
рассматривались самостоятельный backend, вертикальный срез с подключением
браузера к API и основа для деплоя с контейнеризацией. Отдельно обсуждались
компактный каркас и предварительное введение слоёв handler/service/repository.

## Решение

Создать самостоятельный Go-модуль в `backend/` с точкой входа `cmd/server`
и внутренними пакетами для HTTP, конфигурации и жизненного цикла сервера.
Команды разработки и CI выполнять из `backend/`.

Выбран компактный каркас: бизнес-слои и интерфейсы добавляются вместе с реальными
сценариями. Подключение frontend, совместный запуск и инфраструктура деплоя
отложены. Общая версия продукта и существующий release-процесс сохраняются.

## Последствия

- Backend можно собирать и проверять без Node.js, браузера и frontend.
- Структура не закрепляет заранее границы ещё отсутствующей бизнес-логики.
- Будущая интеграция компонентов потребует отдельной задачи.
- Перенос Go-модуля после появления импортов и CI потребует согласованных
  изменений путей; отдельный модуль не означает отдельный продукт или релиз.

## Почему решение сохранено

Это реальный выбор между независимым компонентом и ранней интеграцией, а также
между минимальной структурой и заранее заданными слоями. Он объясняет отсутствие
связи с готовым frontend и служит контекстом для дальнейшего развития каркаса.
