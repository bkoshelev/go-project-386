# ADR-0002: Node.js LTS и pnpm

Статус: принято.

## Контекст

В репозитории нет сложившегося frontend-окружения. Для воспроизводимой установки
нужно выбрать Node.js и пакетный менеджер. В интервью был предложен npm
с lock-файлом; пользователь выбрал pnpm и самую последнюю LTS-версию Node.js.

## Решение

Использовать pnpm и последнюю LTS-версию Node.js на момент реализации.
Зафиксировать выбранные версии в проекте и использовать их локально и в CI.
Хранить `pnpm-lock.yaml`; в CI устанавливать зависимости без изменения lock-файла.

Точный номер Node.js и совместимую версию pnpm проверить при реализации.
Выбор «последней LTS» не означает плавающее обновление окружения на каждом запуске.

## Последствия

- Разработчику потребуется установленный pnpm; инструкции должны описывать
  подготовку окружения.
- Локальная установка и CI используют один пакетный менеджер и lock-файл.
- Обновления Node.js и pnpm в дальнейшем выполняются явно с проверкой сборки
  и smoke-теста.
- Lock-файлы других пакетных менеджеров в этой задаче не создаются.

## Почему решение сохранено

Выбор pnpm сделан явно в ответ на альтернативу npm. Он влияет на команды,
lock-файл и настройку CI; поздняя замена потребует согласованных изменений.
