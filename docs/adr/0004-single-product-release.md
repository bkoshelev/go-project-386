# ADR-0004: Единая версия и единый поток релизов продукта

Статус: принято.

## Контекст

В репозитории уже есть самостоятельный фронтенд, а Go-бэкенд будет добавлен
отдельно. При внедрении release-please нужно определить единицу версионирования:
выпускать весь сервис одной версией либо вести независимые релизы компонентов.

В интервью рассматривались следующие варианты:

- Одна версия всего продукта и теги `vX.Y.Z`.
- Отдельный frontend-компонент с тегами наподобие `frontend-vX.Y.Z`, а в будущем
  отдельный цикл версий бэкенда.

## Решение

Считать весь сервис одной единицей релиза. Настроить один корневой компонент
release-please, один `CHANGELOG.md` и теги вида `vX.Y.Z` без имени компонента.
Фронтенд и будущий Go-бэкенд должны входить в один release PR и получать общий
номер версии.

Приватный `frontend/package.json` не является источником общей версии и остаётся
с техническим значением `0.0.0`. Текущая версия продукта хранится в manifest
release-please, Git-тегах и GitHub Releases.

## Последствия

- Пользователь видит одну последовательность версий и один changelog продукта.
- Изменение любого пользовательски значимого компонента может повысить общую
  версию.
- Фронтенд и бэкенд нельзя независимо обозначить как выпущенные версии в рамках
  принятой схемы.
- Компоненты должны быть совместимы на уровне каждого общего релиза.
- Если позже понадобятся независимые циклы поставки, потребуется изменить
  manifest, схему тегов и правила формирования changelog. Уже опубликованные
  общие теги останутся частью истории и потребуют явного плана перехода.
- Отказ от обновления `frontend/package.json` можно пересмотреть независимо от
  общей схемы релизов, если версия понадобится приложению во время выполнения.

## Почему решение сохранено

Решение удовлетворяет всем критериям для ADR:

- После публикации релизов его трудно обратить без смены схемы тегов и сохранения
  исторической совместимости.
- Единая версия для раздельно расположенных frontend и backend может удивить
  читателя без знания продуктового контекста.
- В интервью был сделан реальный выбор между общим релизом и независимыми
  релизами компонентов.
