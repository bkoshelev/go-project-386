# Миграции при запуске контейнера и совместимость соседних версий

Статус: принято по ответам пользователя 20 октября 2026 года;
реализовано 20 октября 2026 года.

Обычный запуск контейнера применяет встроенные миграции goose до запуска
HTTP-сервера. Это позволяет запускать образ с внешней PostgreSQL без
обязательного платформенного шага перед деплоем; отдельная команда миграций
сохраняется для ручного запуска и сценариев платформы.

Применение защищается блокировкой в PostgreSQL и ограничивается по времени:
несколько запускающихся контейнеров не должны одновременно изменять схему.
Ошибка миграции завершает запуск с ошибкой, приложение не принимает трафик.
Подключение с ограниченными повторами при временной недоступности БД,
ожидание блокировки и миграции вместе ограничены пятью минутами.

Блокировка миграторов не защищает старый работающий экземпляр от несовместимой
схемы. Поэтому автоматические миграции должны быть совместимы с предыдущей
версией приложения; удаление старых структур выполняется последующим выпуском
после перевода кода на новые. Откат образа не запускает `down` и не отменяет
уже применённые изменения схемы.

Решение развивает инфраструктуру из
[ADR-0014](0014-postgresql-and-sqlc.md).
