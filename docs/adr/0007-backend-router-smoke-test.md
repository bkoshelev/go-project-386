# ADR-0007: Smoke-тест через Gin-роутер без запуска процесса

Статус: принято.

## Контекст

Для минимального backend нужен сохраняемый smoke-тест. Рассматривались запуск
собранного бинарника, HTTP-сервер внутри теста и проверка уже запущенного сервиса.
После уточнения рекомендаций Gin пользователь выбрал стандартные `testing`
и `httptest.NewRecorder` с assertions через testify.

В существующем frontend smoke-тест запускает production-сборку в браузере.
Одинаковое название проверок может создать ошибочное ожидание такой же глубины
проверки backend.

## Решение

Проверять `GET /healthz` через `ServeHTTP` общего роутера приложения, используя
`httptest.NewRecorder` и testify. Проверять статус, Content-Type и JSON.
Не открывать порт и не запускать отдельный процесс в smoke-тесте.

Включить проверку в `go test ./...`, отдельно проверять сборку в CI. Жизненный
цикл сервера покрыть дополнительными тестами, а запуск собранного бинарника,
HTTP-ответ и остановку по сигналу проверить при реализации задачи.

## Последствия

- Smoke быстрый, не зависит от свободного порта или заранее запущенного сервиса.
- Он проверяет регистрацию маршрута, обработчик и middleware приложения.
- Он не доказывает корректность `main`, чтения окружения, сетевого запуска
  бинарника и обработки сигналов; сборка в CI также не заменяет запуск процесса.
- В тестах появляется testify как явно выбранная зависимость для assertions.
- Более глубокая автоматическая проверка бинарника может быть добавлена позже.

## Почему решение сохранено

Это результат реального выбора глубины тестирования. Ограничение особенно важно
для читателя, знакомого с более широким frontend smoke-тестом: название smoke
само по себе не означает проверку отдельного процесса.
