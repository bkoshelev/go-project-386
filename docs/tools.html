Архитектурные паттерны

Feature-Based Architecture

Модули по функциям продукта с небольшими публичными API; композиция экранов находится выше функций.

Vertical Slice Architecture

Конкретный сценарий от входа до результата: HTTP-адаптер, предметные правила и SQL; общая инфраструктура сохраняется.

Event-Driven Architecture (EDA) с конечными автоматами (FSM)

Событийная архитектура: локальные события и XState описывают допустимые состояния и переходы интерфейса; результаты эффектов возвращаются в автомат.

Workflow-based architecture

Функции-координаторы выполняют шаги запросов и возвращают результаты в FSM. Для коротких сценариев не требуется долговечный движок.

Практики разработки

API Design-first

Сначала контракт TypeSpec/OpenAPI; затем генерация Fetch-клиента Hey API и HTTP-слоя Go через oapi-codegen. Обработчики реализуют согласованный контракт.

Spec Driven Development (SDD)

Сначала согласуются поведение, ограничения и критерии приёмки в спецификации, затем выполняются реализация и проверка соответствия.

Architecture Decision Record (ADR)

Фиксация контекста, выбранного решения, причин и последствий. Общие архитектурные решения frontend и backend сохраняют обоснование выбора.

Загрузка раскладки…

При открытии автоматически загружается соседний state.js, в том числе через file://. Сервер и специальные настройки браузера не нужны. Если файл недоступен или повреждён, используется встроенная раскладка.

«Сохранить» записывает или скачивает только координаты групп. Для следующего открытия поместите файл рядом с tools.html под именем state.js. Скачивание в другое место не обновляет исходный файл.

Каталог встроен в HTML и обновляется вручную. Архитектурные карточки описывают документированные подходы и выбранные границы, а не полноту их реализации.
