# Domain Docs

Правила чтения доменной документации инженерными скиллами, явно названными пользователем.
Эти правила не разрешают автоматически вызывать другие скиллы.

## Структура: single-context

В репозитории один контекст доменной документации для `backend/` и `frontend/`:

- `GLOSSARY.md` в корне — общий словарь предметной области.
- `docs/adr/` — общие архитектурные решения.

## Перед изучением кода

- Прочитайте `GLOSSARY.md`, если он существует.
- Прочитайте ADR из `docs/adr/`, относящиеся к области задачи.
- Если в будущем появится корневой `GLOSSARY-MAP.md`, прочитайте его и указанные в нём словари релевантных контекстов.

Если документа нет, продолжайте без замечаний о его отсутствии и без предложения создать его заранее.
Не создавайте пустой глоссарий при настройке. Термины и решения документируются по мере их согласования.
Скилл `domain-modeling` можно использовать для этого только при явном вызове пользователем.

## Терминология

В названиях задач, предложениях по рефакторингу, гипотезах и тестах используйте термины из глоссария.
Избегайте синонимов, от которых глоссарий явно отказывается.
Если нужного понятия нет, проверьте принятую терминологию; при реальном пробеле отметьте его для последующего уточнения.

## Конфликты с ADR

Если предложение противоречит существующему ADR, явно укажите номер решения и причину пересмотра.
Не переопределяйте архитектурные решения молча.
