# Минимальный запуск фронтенда

Статус: спецификация по результатам интервью; реализация ещё не начата.

## Цель

Добавить минимальную frontend-часть на Vite, Mantine и TypeScript, страницу для
проверки её работы и сохраняемый браузерный smoke-тест. Разработчик должен иметь
возможность установить зависимости, запустить страницу и одной командой проверить
production-сборку. Та же проверка должна выполняться в GitHub Actions.

## Исходное состояние

- Проект — сервис бронирования календаря, но продуктовые сценарии не входят в эту задачу.
- На момент интервью в репозитории нет frontend- и backend-кода.
- Есть README и существующий workflow `.github/workflows/hexlet-check.yml`.
- Бэкенд будет добавлен отдельной задачей.

## Согласованные требования

### Размещение и запуск

- Фронтенд размещается в самостоятельной папке `frontend/`.
- Установка, разработка, сборка и тестирование запускаются из этой папки.
- Единая команда запуска из корня, pnpm workspace и интеграция с Go не нужны.
- Для работы страницы и тестов не нужен API или другой прикладной сервис.

### Инструменты и версии

- Сборщик и сервер разработки: Vite.
- UI: React и Mantine.
- Язык исходного кода: TypeScript с проверкой типов.
- Node.js: последняя LTS-версия, актуальная на момент реализации. Точный номер
  необходимо проверить перед настройкой, а не выводить из версии, установленной
  на машине разработчика.
- Пакетный менеджер: pnpm.
- Выбранные версии Node.js и pnpm должны быть явно зафиксированы в проекте и
  согласованы между локальной разработкой и CI. Автоматический переход на будущую
  LTS-ветку при каждом запуске не требуется.
- `pnpm-lock.yaml` хранится в репозитории. CI устанавливает зависимости без
  изменения lock-файла.
- Версии Vite, React, Mantine, TypeScript и тестовых инструментов должны быть
  совместимы с выбранным окружением.

### Проверочная страница

- Страница загружается по корневому адресу приложения.
- Она содержит заголовок и оформленные компоненты Mantine.
- Есть кнопка Mantine, открывающая модальное окно Mantine.
- Окно закрывается по Escape.
- Подключены необходимые стили и провайдер Mantine.
- Исходный код страницы написан на TypeScript/TSX.
- Страница минимальна: достаточно показать, что приложение рендерится,
  стили применяются и взаимодействие работает.
- Нет запросов к API, авторизации и сценариев бронирования.

Само отображение страницы не подтверждает корректность типов. Поэтому проверка
TypeScript должна быть отдельным обязательным шагом сборочной команды:
ошибка типов приводит к ненулевому коду завершения сборки.

### Браузерная проверка

- Тест хранится в репозитории и запускается одной командой после первоначальной
  подготовки окружения.
- Команда проверяет типы, создаёт production-сборку и тестирует именно её.
- Локальный сервер собранных файлов запускается автоматически для теста и
  завершается после него, в том числе при падении проверки.
- Не требуется заранее запускать сервер вручную.
- Тест не должен случайно использовать ранее запущенное чужое приложение.
- Установка браузера — явный шаг первоначальной подготовки после `pnpm install`.
  Обычная тестовая команда не устанавливает браузер автоматически.
- Тест проверяет загрузку страницы, наличие заголовка и кнопки, открытие
  модального окна после нажатия и его закрытие по Escape.
- Ошибка сборки, запуска сервера или браузерного сценария завершает команду
  с ненулевым кодом.
- Запуск сервера разработки также проверяется при выполнении задачи.

### GitHub Actions

- Добавляется отдельный workflow для фронтенда.
- Существующий `.github/workflows/hexlet-check.yml` не изменяется.
- Workflow устанавливает согласованные Node.js и pnpm, зависимости из lock-файла,
  браузер и необходимые системные зависимости, затем запускает ту же команду
  smoke-теста, что используется локально.
- Сбой любого обязательного шага делает проверку неуспешной.
- Проверка должна работать в чистом окружении runner, без локальных файлов
  разработчика и без бэкенда.

### Документация и служебные файлы

- Документация содержит требования к Node.js и pnpm, первоначальную установку,
  запуск разработки, сборку и запуск браузерного теста.
- Отдельно указано, что браузер устанавливается один раз при подготовке окружения;
  после обновления тестового инструмента может потребоваться повторная установка.
- Зависимости, результаты сборки и артефакты тестов исключены из Git.
- Lock-файл, тесты, конфигурация и инструкции включены в Git.

## Предлагаемые детали реализации

Эти детали конкретизируют согласованный результат, но не являются отдельными
решениями пользователя об архитектуре. Их можно уточнить при реализации,
сохранив требования выше.

- Playwright Test и Chromium для единственного smoke-сценария.
- `.nvmrc` в `frontend/` для выбранной версии Node.js и `packageManager` в
  `package.json` для версии pnpm.
- `pnpm dev` — запуск Vite для разработки.
- `pnpm build` — проверка TypeScript и production-сборка Vite.
- `pnpm exec playwright install chromium` — первоначальная установка браузера.
- `pnpm test:smoke` — сборка и браузерная проверка с управляемым сервером.
- Vite preview — локальная раздача собранных файлов для smoke-теста; это не
  решение о сервере для будущего production-развёртывания.
- В CI установка браузера выполняется с системными зависимостями, например
  `pnpm exec playwright install --with-deps chromium`.
- Новый workflow запускается на push и pull request.
- Минимальная структура: `package.json`, lock-файл, HTML-точка входа, исходники
  в `src/`, настройки Vite и TypeScript, конфигурация Playwright и smoke-тест.

## Не входит в задачу

- Бэкенд, API, проксирование к Go и совместный запуск frontend/backend.
- Продуктовые экраны календаря, авторизация, маршрутизация и управление данными API.
- SSR, SEO, деплой, выбор production-хостинга и Docker-инфраструктура.
- Библиотека собственных UI-компонентов, Storybook и расширенная дизайн-система.
- Матрица нескольких браузеров, визуальные regression-тесты и дополнительные
  наборы unit-тестов.
- Настройка линтера и форматтера как самостоятельная часть этой задачи.

## Критерии приёмки

1. После чистого клонирования можно перейти в `frontend/`, подготовить указанные
   Node.js и pnpm и выполнить `pnpm install` по документации.
2. Команда разработки запускает страницу без бэкенда; компоненты Mantine
   оформлены, кнопка открывает модальное окно, Escape его закрывает.
3. Сборочная команда проверяет типы и создаёт production-артефакты.
4. После отдельной первоначальной установки браузера одна команда собирает
   приложение, запускает сервер, успешно выполняет smoke-тест и завершает сервер.
5. Тест проверяет собранное приложение в настоящем браузере, а не только
   HTTP-ответ или наличие файлов сборки.
6. Новый workflow воспроизводит установку и smoke-тест в чистом окружении.
7. Существующая проверка Хекслета сохранена без изменений.
8. В репозитории есть воспроизводимые конфигурация, lock-файл, тест и инструкции;
   нет установленных зависимостей и сгенерированных артефактов.

При завершении реализации необходимо указать фактически выполненные проверки.
Локальная успешная проверка не считается доказательством успешного запуска
GitHub Actions: если workflow ещё не запускался на GitHub, это отмечается отдельно.
