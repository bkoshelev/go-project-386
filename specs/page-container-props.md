# Явная конфигурация контейнера страниц

Статус: **Реализована; старт одобрен пользователем**.

## Ожидаемое поведение и объём

В `frontend/src/App.tsx` заменить условные значения props основного `Container`
на объект конфигурации с отдельной записью для каждой страницы. Объект содержит
JSON-совместимые значения и проверяется TypeScript на соответствие props Mantine.
Расположить конфигурацию на уровне модуля, вне React-компонента.

Предлагаемое содержимое:

```json
{
  "/": {
    "component": "main",
    "size": "md",
    "px": { "base": "md", "sm": "xl" },
    "py": { "base": 64, "sm": 96 }
  },
  "/admin": {
    "component": "main",
    "size": "xl",
    "px": { "base": "md", "sm": "xl" },
    "py": 28
  },
  "/admin/availability": {
    "component": "main",
    "size": "md",
    "px": { "base": "md", "sm": "xl" },
    "py": { "base": 64, "sm": 96 }
  },
  "/book": {
    "component": "main",
    "size": "md",
    "px": { "base": "md", "sm": "xl" },
    "py": { "base": 64, "sm": 96 }
  }
}
```

Выбранную запись передавать в основной `Container` через spread props.
Для `/admin` и `/admin/availability` сохранить точное сопоставление путей.
Все пути с префиксом `/book` используют конфигурацию `/book`, как при текущем
выборе компонента `Booking`. Остальные пути используют конфигурацию главной.
Шаги бронирования находятся внутри одной страницы и используют одну конфигурацию.

## Ограничения

- Сохранить существующие размеры, адаптивные отступы и содержимое страниц.
- Не изменять контейнер шапки, навигацию и логику маршрутизации.
- Не добавлять React state: конфигурация статична и выбирается по текущему пути.
- Не добавлять зависимости и не затрагивать backend или API.

## Критерии приёмки

- Все четыре страницы явно перечислены в объекте с полным набором props.
- В JSX основного `Container` отсутствуют условные выражения для `size` и `py`.
- Значения props для известных и остальных путей совпадают с текущими.
- TypeScript проверяет конфигурацию; форматирование и lint изменённого файла проходят.

## Проверка

Проверить типы frontend и запустить lint и проверку форматирования `App.tsx`.
Сверить выбор конфигурации для `/`, `/admin`, `/admin/availability`, `/book`,
пути с префиксом `/book` и неизвестного пути. Новые тесты, повторяющие
статический объект, не требуются.

Результаты проверки:

- `pnpm --dir frontend exec tsc -b` — успешно.
- `pnpm --dir frontend exec oxlint src/App.tsx` — успешно.
- `pnpm --dir frontend exec oxfmt --check src/App.tsx` — успешно.
- Сравнение выбранных props с прежними выражениями для девяти путей,
  включая страницы, префикс `/book`, `/admin/` и неизвестные пути — успешно.
