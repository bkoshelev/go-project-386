## Цель и результат

Создать русскоязычную HTML-документацию об инструментах календарного бронирования
в виде интерактивной карты по образцу, исследованному в
[packages-html-reference.md](../docs/research/packages-html-reference.md).

Результат реализации:

- `docs/tools.html` — самостоятельная страница со встроенными CSS, JavaScript и каталогом.
- `docs/state.js` — исходная сохранённая раскладка групп и формат её дальнейшего экспорта.
  Он заменил `docs/state.json`; обратная совместимость не нужна.

Страница работает отдельно от frontend и backend, без их сборки и запуска,
внешних библиотек, CDN и загрузки шрифтов. Список инструментов обновляется вручную
в HTML; генератор каталога не требуется.

По уточнению пользователя карта реализуется на Web Components, как образец:
`tool-canvas`, `tool-group` и `tool-node`, зарегистрированные через
`customElements.define`. Разметка остаётся в обычном DOM, без Shadow DOM.

HTML и соседний `state.js` должны работать при прямом открытии через `file://`
в обычном Chrome без специальных флагов и без HTTP-сервера. Через HTTP загрузка
также сохраняется. Если раскладка недоступна, карта использует встроенные
координаты. Каталог и Web Components остаются внутри HTML.

## Правила включения

Каталог отражает текущий проект, а не стек приложения из образца.

1. Включить все `dependencies` и `devDependencies` из `frontend/package.json`
   и `api/package.json`, прямые Go-зависимости, явно объявленные Go tools,
   инструменты окружения, тестирования, CI/CD и инфраструктуры проекта.
2. Основание включения — действующие манифесты, конфигурации, команды
   и документация обязательных или явно описанных дополнительных сценариев проекта.
   Историческое упоминание удалённого инструмента или рассмотренной альтернативы
   не является основанием включения. Исключение по явному запросу пользователя:
   OpenSpec, Render.com и Dev Containers показываются в группе «Еще не внедрено»,
   с явным статусом отсутствия внедрения в проекте.
3. Транзитивные зависимости не включать. В частности, записи `// indirect`
   в `go.mod` и зависимости только из lock-файлов не считать прямым выбором.
   Исключение: `oapi-codegen` явно объявлен директивой `tool` и должен присутствовать,
   хотя его модуль также записан как `// indirect`.
4. Объединять пакеты одного семейства в карточку, перечисляя точные имена прямых
   пакетов. Все прямые зависимости должны оставаться представленными.
   Например, карточка Mantine перечисляет `@mantine/core`, `@mantine/dates`
   и `@mantine/hooks`; React — также `react-dom` и соответствующие `@types`.
5. Повторяющийся инструмент показывать один раз с указанием областей использования.
   Встроенные команды toolchain, анализаторы и плагины не превращать в отдельные
   установленные инструменты: описывать их внутри соответствующего семейства.
6. Показывать название, краткое назначение именно в этом проекте, имена объединённых
   пакетов и при необходимости область использования. Версии и ссылки на файлы
   в карточках отсутствуют. Не добавлять ссылки на исходники другим способом.
7. Включить все локальные скиллы и только MCP-серверы, настроенные в репозитории.
   По отдельному запросу добавить установленный в окружении Orca скилл
   `orchestration`, явно отличая его от локальных скиллов репозитория. Plannotator
   включить как инструмент документированного ревью. Другие доступные агентной
   сессии средства автоматически в каталог не добавляются.
8. Для архитектуры включить основные подходы из `docs/architecture/`
   и паттерны, явно выбранные в ADR. Подходы, приведённые только для сравнения,
   иллюстрации или как отвергнутые варианты, исключить. Не выводить паттерны из кода
   по косвенным признакам и не приписывать им статус полной реализации.

## Внешний вид и поведение

Сохранить характер образца: светлая сине-серая палитра, сетка холста,
центральная карточка приложения, светлые группы и вложенные карточки инструментов.
Расположение и размеры адаптировать к фактическому количеству карточек;
текст и списки пакетов не должны обрезаться или перекрывать соседние группы.
Расширение каталога допускает изменение размеров и исходных координат групп:
встроенная раскладка и `state.js` должны совпадать и вмещать новые карточки.

- При открытии вписать все группы и центральный узел в видимую область
  после применения сохранённой либо встроенной раскладки.
- Кнопки `+`/`−` масштабируют относительно центра окна, колесо — относительно
  указателя; индикатор показывает текущий масштаб.
- Перетаскивание фона или центрального узла перемещает камеру.
- Перетаскивание группы, включая её карточки, перемещает всю группу
  с учётом масштаба; координаты округляются до целых.
- `Сбросить вид` вписывает текущую раскладку в окно, не меняя координат групп
  и признака несохранённых изменений. Начальный вид и сброс используют одно правило.
- Изменение координат группы показывает кнопку «Сохранить»;
  перемещение камеры и масштабирование этого не делают.
- Использовать обычные доступные кнопки с понятными названиями.
  На узком экране элементы управления остаются доступны, карта не открывается
  пустым участком сетки. Масштаб должен позволять приблизить карточки для чтения.

Поиск, фильтры, связи между инструментами, редактор содержимого, встроенный
генератор каталога и интеграция с приложением в согласованный объём не входят.

## Загрузка и сохранение раскладки

`state.js` — обычный скрипт с единственным присваиванием данных:

```js
window.toolsMapState = {
  "groups": {
    "frontend": { "x": 100, "y": 200 }
  }
};
```

Значения примера иллюстративны. Идентификаторы групп должны быть стабильными
и совпадать в HTML и объекте состояния. Исходный `docs/state.js` содержит все
двенадцать групп с координатами актуальной раскладки, включая две новые группы.

При открытии загрузить соседний `./state.js` как обычный classic script через
элемент `<script>`, без `type="module"`, `fetch`, XHR и динамического `import`.
Параметр против кэширования должен обеспечивать чтение свежей раскладки при новом
открытии через HTTP. Файл должен загружаться и через `file://`; настройка Chrome,
изменение MCP-конфига и HTTP-сервер для этого не требуются.

После завершения загрузки прочитать `window.toolsMapState` и применить корректные
конечные координаты известных групп; для отсутствующих или некорректных записей
оставить встроенные значения. Неизвестные ID не создают группы. Отсутствующий файл,
неуспешная загрузка, синтаксическая ошибка или отсутствие корректного объекта
состояния не блокируют карту: применяется встроенная раскладка и показывается
понятное сообщение. Перетаскивание разрешается после завершения загрузки или
обработки ошибки; затем вся текущая карта автоматически вписывается в окно.

Нормализация сохранена по правилам образца: координаты приводятся
через `Number`, затем проверяются на конечность; строковые числа допускаются,
`null` преобразуется в `0`. Резервные координаты хранятся в атрибутах `x`/`y`
компонентов групп. Смена способа загрузки сохраняет эти правила нормализации.

«Сохранить» экспортирует `state.js` с присваиванием `window.toolsMapState` объекту,
содержащему только координаты всех групп. Камера, масштаб, содержимое карточек
и центральный узел в экспорт не входят. Если доступен `showSaveFilePicker`,
предложить имя `state.js`, расширение `.js` и MIME `text/javascript`; иначе скачать
тот же файл. Отмена выбора не сбрасывает признак изменений, ошибка записи
понятно сообщается пользователю. После успешной записи либо запуска скачивания
кнопка скрывается. Не заявлять, что скачивание автоматически обновило файл репозитория.

Для следующей загрузки файл должен находиться рядом с `tools.html` под именем
`state.js`. Подсказка на странице объясняет это и сообщает о работе через `file://`.
Скачивание в другое место само по себе исходник не заменяет. Требование HTTP,
подсказка о CORS для JSON и старое имя экспорта удаляются. `localStorage`, импорт
через форму, поддержка старого JSON и экспорт всего HTML не требуются.

## Ограничения реализации
