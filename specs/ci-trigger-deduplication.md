# Устранение двойных запусков CI

Статус: реализована; старт явно одобрен пользователем 8 ноября 2026 года
вызовом `$implement`. Проверка событий на GitHub ожидает отправки изменений.

## Цель и ожидаемое поведение

Убрать одновременные запуски одинаковых проверок по событиям `push` и
`pull_request` при обновлении ветки с открытым PR.

Для workflow `backend`, `frontend` и `container` сохранить `pull_request`
с текущими событиями по умолчанию, а `push` ограничить веткой `main`:

```yaml
on:
  push:
    branches: [main]
  pull_request:
```

Проверки PR запускаются при его открытии, обновлении коммитов и повторном
открытии. После слияния или прямого push в `main` запускаются проверки
интегрированной ветки. В остальных ветках без PR эти три workflow не запускаются.
Push тегов также не запускает эти три workflow.

## Объём изменений и ограничения

- Изменить только триггер `push` в `.github/workflows/backend.yml`,
  `.github/workflows/frontend.yml` и `.github/workflows/container.yml`.
- Уточнить описание событий контейнерного smoke в `.github/workflows/README.md`.
- Сохранить имена workflow, jobs, шаги и команды проверок.
- Сохранить настройки `PR title`, `hexlet-check` и `release-please`.
- Отмена устаревших запусков через concurrency и фильтрация по путям
  не входят в эту задачу.

## Критерии приёмки

1. Push в рабочую ветку с открытым PR создаёт один запуск каждого из трёх
   workflow по событию `pull_request`, без второго запуска по `push`.
2. Открытие и повторное открытие PR по-прежнему запускают все три workflow.
3. Push в `main` запускает все три workflow.
4. Push в другую ветку без PR и push тега не запускают эти три workflow.
5. Состав проверок и остальные workflow не изменены; документация соответствует
   новым триггерам.

## Проверка

Проверить итоговый diff и синтаксис workflow через actionlint, если он доступен.
Сверить конфигурацию с перечисленными сценариями событий. После отправки изменений
в GitHub проверить отсутствие запусков этих workflow по событию `push` в рабочей
ветке и успешное выполнение единственного набора проверок PR. Проверку запуска
по `push` в `main` завершить после слияния; не создавать для проверки отдельные
push в `main` или теги.

Локальная проверка 8 ноября 2026 года: `actionlint` 1.7.11 для всех workflow
и `git diff --check` прошли. Изменения в workflow ограничены фильтром ветки
для `push`; jobs и триггеры PR сохранены. Проверка событий на GitHub ещё
не выполнялась.
