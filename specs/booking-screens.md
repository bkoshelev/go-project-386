# Экраны и пользовательские сценарии бронирования

Статус: **сценарии и состояния экранов согласованы пользователем**. Полная
спецификация MVP утверждена 19 октября 2026 года. HTTP-контракт и схема
приложения также приняты.

Каноническая [спецификация приложения](https://github.com/bkoshelev/go-project-386/issues/31)
хранится в GitHub Issues. Это приложение к решению
[«Экраны и пользовательские сценарии»](https://github.com/bkoshelev/go-project-386/issues/27).
Реализация интерфейса в текущую работу не входит.
Сводные требования и критерии приёмки — в [спецификации MVP](booking.md).

## Согласованный путь гостя

Главная → «Записаться» → выбор типа события → календарь и время → имя и email →
подтверждение успешного бронирования. Выбор типа, времени и ввод данных —
последовательные шаги wizard.

| Шаг | Данные и действия |
| --- | --- |
| Тип события | Название, необязательное описание, длительность; выбор типа по ID. |
| Календарь и время | Даты и свободные начала для выбранного типа, ручной ввод начала с точностью до минуты. |
| Данные гостя | Обязательные имя и email; сводка выбранного типа и времени. |
| Подтверждение | Название встречи, дата, начало, окончание и часовой пояс после успешного ответа. |

При возврате назад имя и email сохраняются. Смена типа события сбрасывает выбранное
время. Подтверждение не является действием, требующим согласия владельца: встреча
создана при успешном сохранении.

Встречи отображаются в автоматически определённом часовом поясе браузера гостя.
Верхняя строка записи может содержать «Создать встречу с [Full Name владельца]».
Окно бронирования остаётся равным 14 календарным датам UTC, включая сегодня;
преобразование в местное время не меняет его границ. На экране могут затрагиваться
части дополнительных местных дат: вне окна UTC время выбрать нельзя.

## Согласованные экраны владельца

В nav bar главной находится ссылка «Администрирование» на `/admin`. Используется
один заранее заданный профиль без регистрации и авторизации.

| Раздел | Данные и действия |
| --- | --- |
| Типы событий | Список созданных типов и форма создания: название, необязательное описание, целое значение длительности и переключатель минут/часов. UUID создаёт БД. |
| Доступность | Семь дней недели с интервалами и флагами блокировки, настройки конкретных дат, общая пауза 0–60 минут. |
| Предстоящие встречи | Все бронирования с `endsAt > now`, по началу по возрастанию; без пагинации. |

Встреча, которая уже началась, остаётся в списке до окончания. Владелец видит
название встречи, дату, начало, окончание, часовой пояс, имя и email гостя.

До настройки расписания все дни заблокированы, интервалы пусты, пауза равна 0.
Недельные интервалы сохраняются при блокировке дня недели. Блокировка конкретной
даты удаляет её собственные интервалы; разблокированная дата наследует недельные.
Закрытый в недельном расписании день нельзя открыть настройкой отдельной даты.

Редактор показывает местные дни и часы в первом сохранённом часовом поясе владельца
с явной подписью пояса. Пояс впервые определяется браузером владельца и фиксируется
для календаря; поездки и повторное сохранение настроек его не меняют. Конкретные
встречи отображаются в текущем часовом поясе браузера пользователя.

Сезонный перевод часов вынесен в
[отложенную задачу после MVP](https://github.com/bkoshelev/go-project-386/issues/32).

## Состояния экранов

Пользователь подтвердил предложенные правила для MVP.

| Состояние | Поведение |
| --- | --- |
| Загрузка каталога, календаря или списка встреч | Индикатор загрузки; ошибка загрузки не подменяется пустым списком. |
| Нет типов событий | Гость видит «Пока нет доступных типов встреч». Владелец — пустой список и действие создания типа. |
| Нет слотов на выбранную дату | «На эту дату нет свободного времени»; можно выбрать другую дату в пределах окна. |
| Нет слотов во всём окне | «В ближайшие 14 дней нет свободного времени»; доступно обновление доступности. |
| Нет предстоящих встреч | «Предстоящих встреч пока нет». |
| Не удалось загрузить данные | Сообщение об ошибке и действие «Повторить» для чтения данных. |
| Тип события не найден | Объяснение и возврат к выбору типа; данные гостя в текущем wizard сохраняются. |
| Неверные данные формы | Ошибки рядом с полями; ввод сохраняется, запрос с неверными данными не отправляется. |
| Создание бронирования или сохранение настроек выполняется | Видимый процесс сохранения; повторное нажатие кнопки недоступно до результата запроса. |
| Выбранное время занято или уже недоступно | Сообщение с причиной, обновление слотов, возврат к выбору времени; имя и email сохраняются. |
| Ошибка сохранения с определённым отказом | Сообщение об ошибке, введённые значения остаются в форме; успех не показывается. |
| Ответ создания бронирования потерян | «Не удалось получить результат бронирования». Нет автоматической повторной отправки; пользователь может повторить вручную. |
| Повтор после ранее сохранённого бронирования | Согласованное «Время уже занято» и обновление слотов; прежний успешный ответ не восстанавливается. |
| Сохранение типа события успешно | Новый тип появляется в списке; отображается подтверждение создания. |
| Сохранение доступности успешно | Видно подтверждение сохранения и фактически сохранённые значения. |

Уточнения к этим состояниям:

- Перед переходом из календаря в форму требуется выбрать допустимое время.
- Изменение времени не очищает имя и email. При конфликте сбрасывается только
  ставшее недоступным выбранное время.
- Возврат внутри текущего wizard сохраняет данные в памяти страницы; сохранение
  черновика после перезагрузки страницы или между устройствами не требуется.
- Состояние успеха показывается только по успешному ответу backend.
- Ошибка или неизвестный результат операции записи не запускает её повтор автоматически.
- Если пояс владельца ещё не сохранён, административная часть передаёт определённый
  браузером пояс для однократного сохранения. Ошибка определения/сохранения показывается
  явно, расписание не открывается для бронирования до успешной инициализации.
- В редакторе доступности непустые интервалы проверяются на корректное время,
  начало раньше окончания и отсутствие пересечений в пределах местного дня.
  Ошибки показываются рядом с соответствующим интервалом.

## Общие требования интерфейса

- Рабочая ширина от 320 px: нет наложений и горизонтальной прокрутки страницы,
  все шаги и административные действия доступны. Длинные названия и email переносятся.
- Поля имеют видимые подписи; ошибки связаны с полями. Шаги wizard имеют названия
  и показывают текущий шаг. Активные действия доступны с клавиатуры, фокус видим.
- При переходе шага фокус переходит к его заголовку, при неуспешной проверке —
  к первому ошибочному полю. Сообщения о загрузке, успехе и ошибках доступны
  вспомогательным технологиям; цвет не является единственным способом сообщения.
- Часовой пояс подписан рядом со временем. На административном экране различаются
  сохранённый пояс расписания и пояс отображения конкретных встреч, если они различны.
- Стандартные элементы Mantine используются в рамках текущего стека frontend.

## Сверка с контрактом и главной страницей

- `BookingGuest` содержит согласованные имя и email с ограничениями.
- `CreateBookingRequest`, `BookingConfirmation`, `OwnerBooking` и `OwnerBookings`
  покрывают данные формы, подтверждения и полного списка владельца.
- `WeeklyAvailability`, `DateAvailability`, `SchedulingSettings` и запросы
  инициализации/обновления покрывают основные данные редактора.
- `BookingTimeOccupied` описывает согласованный конфликт. Общая форма ошибок,
  ошибки полей, каталог типов, ответ доступности и HTTP-операции подготовлены
  в [принятом HTTP-контракте](booking-api.md).
- `specs/home-page.md` и ADR-0012 уже дополнены: «Записаться» становится входом
  в wizard, в навигацию добавляется ссылка на `/admin`.

Проверка реализации этих требований будет относиться к будущим тикетам приложения;
в текущей работе проверяются непротиворечивость спецификации и согласованность артефактов.
