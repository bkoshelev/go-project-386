# Окружение локальной разработки и тестовые фикстуры

Статус: утверждено пользователем 20 октября 2026 года как основа реализации.
Реализовано и проверено 20 октября 2026 года.

## Согласованные решения

### Проверка testfixtures

В backend добавляется `github.com/go-testfixtures/testfixtures/v3` и YAML-набор
с одной записью существующей технической таблицы `example_records`.
Общий набор загружается один раз после миграций в тестовую PostgreSQL,
до запуска тестов. Ошибки подготовки завершают проверку неуспешно.

Отдельный интеграционный тест читает запись через sqlc и проверяет её значения.
Каждый обычный тест сохраняет существующую транзакцию с откатом.
Проверки генерации UUIDv7 и цикла миграций сохраняются.

### Роли direnv и mise

Mise устанавливает и выбирает версии инструментов. Direnv загружает локальные
переменные из `.env.local`. `scripts/setup-worktree.sh` использует явные CLI-вызовы
обоих инструментов и не зависит от интерактивных shell hooks.

Совместная интеграция объявлена неподдерживаемой в текущей документации mise,
а `use mise` устарел. Раздельный запуск CLI является решением этого проекта;
его работоспособность проверяется при внедрении.

### Подготовка машины и worktree

Mise и direnv устанавливаются на машине заранее; инструкции включаются в README.
Setup устанавливает закреплённые Go, Node.js и pnpm через mise,
затем выполняет существующие этапы установки зависимостей и проверок.
Установка и запуск явно выбирают только эти три инструмента, чтобы
не устанавливать дополнительные инструменты из родительских конфигураций.

### Источники версий

Версия Go остаётся в `backend/go.mod`, Node.js — в `frontend/.nvmrc`,
pnpm — в `frontend/package.json`. Корневая конфигурация mise читает версии
из этих файлов без отдельного вручную синхронизируемого списка.
Makefile и CI сохраняют существующие источники версий.

### Доверие к конфигурации

Запуск `scripts/setup-worktree.sh` автоматически разрешает выполнение
конфигураций direnv и mise текущего worktree. Подготовка нового рабочего дерева
не требует отдельного ручного разрешения этих конфигураций.

### Локальные переменные

Общий `.envrc` загружает необязательный `.env.local` текущего worktree.
`.env.local.example` показывает доступные настройки без локальных секретов.
`.env.local` и служебные локальные файлы direnv исключаются из Git.
Если `.env.local` отсутствует, setup использует существующие значения
по умолчанию и переменные, переданные вызывающим процессом.

## Критерии приёмки

1. Полный `make test` включает тест чтения YAML-фикстуры через sqlc
   и сохраняет проверки UUIDv7, отката транзакций и миграций.
2. `make test-unit` продолжает работать без Docker.
3. Setup использует direnv и mise через явные CLI-вызовы, устанавливает
   требуемые Go, Node.js и pnpm и сохраняет существующие этапы подготовки,
   включая режим `SETUP_VERIFY=1`.
4. Подготовка не требует nvm, пользовательского каталога Go SDK
   или интерактивных shell hooks. Точные версии инструментов проверяются.
5. Повторный запуск setup допустим. Отсутствие mise или direnv,
   ошибка установки инструментов либо ошибка последующего этапа
   завершают setup неуспешно с понятным сообщением.
6. README описывает установку системных инструментов, запуск setup,
   локальные переменные и подготовку данных интеграционных тестов.

## Проверка реализации

Проверено на macOS amd64 с mise 2026.10.15 и direnv 2.38.2.
CLI и runtime-версии устанавливались во временное окружение;
интерактивные shell hooks и nvm не использовались.

- `make check`: lint, vet, тесты с `-race` и реальной PostgreSQL,
  сборка и govulncheck прошли.
- `make test-unit` прошёл, в том числе с заведомо недоступным Docker socket.
- Обычный setup и повторная подготовка с `SETUP_VERIFY=1` завершились успешно;
  прошли frontend lint, сборка и все 7 тестов Playwright.
- Проверены понятные ошибки при отсутствии direnv/mise и неверном
  `SETUP_VERIFY`, а также загрузка `.env.local` без shell hooks.
- Проверен путь с пробелами и символьными ссылками. Setup нормализует его
  через `cd -P`, чтобы direnv разрешал и загружал один и тот же `.envrc`.

## Границы

Постоянная локальная БД, Docker Compose, предметная схема, автозапуск серверов,
автоматическое копирование env-файлов и назначение портов в задачу не входят.
Существующая установка backend-инструментов через Makefile сохраняется.
Технические инструменты не добавляются в предметный глоссарий.
