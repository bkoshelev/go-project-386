# Общая проверка через граф задач mise

Обновление 18 ноября 2026: схема единого job и протокол измерения пересмотрены в [спецификации CI](ci-performance-grilling.md); исторические данные ниже сохранены.

Статус: **Реализована; критерий времени CI не выполнен**.

Последний измеренный CI на реализации графа: [332 с](evidence/mise-check-graph-ci.json)
при пороге 216,7 с. Изменения в рабочем коде одобрены пользователем.

## Ожидаемое поведение

`mise run check` использует граф задач mise вместо координатора `scripts/check.sh`.
Независимые задачи выполняются параллельно, общие зависимости — один раз за запуск.
Проверка TypeSpec, генерация OpenAPI, Go API и SDK, проверка Go-файлов относительно
индекса Git, `backend:check`, проверки frontend, production-сборка, браузерные тесты
и контейнерный smoke остаются в общем наборе. Удалённые ранее `scripts/tests` и
`workflow:test` не восстанавливаются.

В графе генерация Go API и SDK зависит от завершения генерации OpenAPI. Проверка
свежести Go API, backend-проверки и контейнерный smoke начинаются только после
успешной генерации Go API. Frontend-проверки начинаются после генерации SDK;
сборка frontend — после этих проверок, браузерные тесты — после сборки. Проверка
TypeSpec независима от генерации OpenAPI. Генерация сохраняемых Go-файлов по-прежнему
выполняется в рабочем дереве и сравнивается с индексом Git.

Используется обычная обработка ошибок mise без `--continue-on-error`: ошибка любой
задачи останавливает запуск оставшихся задач и может прервать уже выполняющиеся,
в том числе независимые. В частности, несовпадение Go-файлов с индексом может
прервать проверки backend и контейнера. Это намеренное изменение прежнего требования
продолжать независимые проверки и запускать backend и контейнер при таком несовпадении.
Причины ошибок остаются видны в журнале mise.

## Объём и ограничения

- Описать граф средствами задач mise и удалить `scripts/check.sh`; не заменять его
  другим собственным координатором, маркерами статуса или обработчиком ошибок.
- Сохранить самостоятельные команды генерации, frontend-проверок и сборки;
  обычные backend-команды не требуют TypeSpec в соответствии с ADR-0013.
- Обновить README, AGENTS.md и документацию workflow в части поведения при ошибках.
- Не менять бизнес-логику, API-контракт, версии инструментов и состав оставшихся тестов.

## Критерии приёмки и проверка

1. `mise run check` и существующий CI job выполняют указанный состав через граф mise;
   независимые ветки пересекаются, общая генерация каждого вида выполняется один раз.
2. Проверки не читают результат незавершённой генерации; отдельные команды продолжают
   выполнять необходимые зависимости.
3. Контролируемые ошибки генерации и независимых задач в изолированной копии приводят
   к ненулевому коду и демонстрируют обычную остановку mise; при успехе код равен 0.
4. Выполнены полный локальный `mise run check`, `git diff --check` и проверка workflow;
   результат фактического CI и время от создания workflow до окончания job записаны.
5. Ранее согласованный порог 216,7 с остаётся критерием: при его превышении представить
   результат и согласовать дальнейшую схему, не повторяя замер ради удобного результата.
