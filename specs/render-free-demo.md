# Подготовка бесплатного демо на Render

Статус: первый этап реализован и проверен локально 17 ноября 2026 года.

Пользователь выбрал бесплатное демо и отдельно разрешил начать реализацию.
Эта спецификация описывает первый этап — подготовку репозитория
и локальную проверку перед развёртыванием.

## Ожидаемое поведение

- Render собирает один Docker Web Service из корня репозитория по существующему
  `Dockerfile`. Frontend и API работают на одном origin.
- Web Service и отдельная Render Postgres 18 используют явно заданный тариф
  `free` и один регион `frankfurt`.
- Предлагаемые имена ресурсов: `calendar-demo` и `calendar-demo-db`.
- `DATABASE_URL` получается через ссылку Blueprint на внутреннюю строку
  подключения БД; секрет не записывается в репозиторий.
- Внешние подключения к БД отключены через `ipAllowList: []`.
- Приложение запускается стандартной командой образа `/app/server`, получает
  порт через `PORT` и применяет существующие миграции до открытия HTTP.
- Проверка Render использует `/readyz`.
- Для ветки `main` задаётся автоматический деплой после успешных CI-проверок;
  для его работы требуется подключение GitHub к Render.

## Объём изменений

1. Добавить корневой `render.yaml` с Web Service, Postgres и связью между ними.
2. Обновить раздел Render в `docs/runbooks/production-environment.md`:
   создание Blueprint, подключение GitHub, проверка деплоя и ограничения Free.
3. Проверить конфигурацию Blueprint и выполнить `mise run container:test`.
4. Исправления кода приложения или инфраструктуры сборки, обнаруженные
   проверкой и выходящие за этот объём, сначала представить пользователю.

## Ограничения

- Free Web Service засыпает после 15 минут без входящего трафика.
- Free Postgres действует 30 дней и не предоставляет резервное копирование.
- Это демонстрационная среда с тестовыми данными.
- Архитектура приложения, API, существующие миграции и Dockerfile сохраняются.
- Создание ресурсов Render, подключение MCP, авторизация, публикация изменений
  в GitHub и фактический деплой выполняются следующими шагами.
- Платные ресурсы и автоматический переход на платный тариф не включаются.

## Критерии приёмки и проверка

- AC-01: `render.yaml` явно задаёт бесплатные тарифы, PostgreSQL 18,
  общий регион, корневой контекст Docker и `/readyz`.
- AC-02: в YAML нет секретов, `DATABASE_URL` ссылается на БД Blueprint;
  `HTTP_ADDR` не переопределяет порт платформы.
- AC-03: конфигурация проходит проверку по актуальной схеме Blueprint либо
  валидатором Render. Способ и результат фиксируются в отчёте.
- AC-04: `mise run container:test` успешно проверяет сборку и работу готового
  образа с PostgreSQL. Локальная проверка не считается проверкой Render.
- AC-05: инструкция позволяет выполнить следующий этап через Dashboard
  и описывает ограничения бесплатной БД и сервиса.

После фактического деплоя отдельно проверяются HTTPS, главная и вложенная
страницы SPA, `/readyz`, работа API из браузера и сохранность тестовых данных
после перезапуска приложения.
